# Rhai hooks: execution phases and safety

Only add a hook when configuration/Liquid cannot handle the behavior. All hooks operate with access to generation-time data; system command hooks are a security boundary.

```toml
[hooks]
init = ["init.rhai"]
pre = ["pre.rhai"]
post = ["post.rhai"]
```

## Execution phases

| Phase | Timing and available state | Intended use |
| --- | --- | --- |
| `init` | Very beginning, before most values are collected; `crate_type`, authors, username, `os-arch`, `is_init` available; `project-name` may be unavailable | Set or prompt for project name if truly necessary. |
| `pre` | After placeholders and conditional resolution | Add derived variables, rename/delete temporary template assets. Too late to influence conditions. |
| `post` | After template rendering, before moving files to their final destination | Inspect or transform generated temporary files. |
| `post = ["fmt"]` | Built-in named formatter (v0.26+), runs on final destination | Re-enable formatting even when template sets `fmt=false`. |

`fmt` in `init` or `pre` is ignored with a warning. A file named `fmt.rhai` is not reserved.

## Rhai API essentials

```rhai
let kind = variable::get("crate_type");
variable::set("derived_key", "derived-value");
if file::exists("unwanted.txt") {
    file::delete("unwanted.txt");
}
file::write("metadata.txt", "Generated by cargo-generate");
```

Supported helper families include `variable::{get,is_set,set,prompt}`, `file::{exists,rename,delete,write,listdir}`, `system::{date,command}`, `env::{working_directory,destination_directory}`, and `abort("reason")`. Template folder paths used by the `file` module must stay inside the working template area.

## System commands (high risk)

```rhai
let result = system::command("rustc", ["--version"]);
```

Commands execute on the user's machine through a shell. The CLI normally prompts for consent; `--silent` fails when such commands are needed unless the caller also passes `--allow-commands`. `--allow-commands` permits arbitrary command execution without further confirmation. Do not suggest it as a default or introduce command-execution hooks without making their behavior explicit. Never interpolate unchecked user input into shell commands; arguments are joined to shell text without automatic escaping.

Prefer native formatting rather than `system::command("cargo", ["fmt"])` in a hook: working-directory behavior can differ across platforms.
